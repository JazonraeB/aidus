# AIDUS — AI Development Usage Specification

AIDUS is an open, provider-neutral format for recording the **AI usage behind a software project** inside the repository itself: tokens, models, sessions and cost, never content.

```text
.ai-usage/
├── project.json                    # who this project is
├── usage.json                      # derived summary (AIDUS 1.0 compatible)
└── events/2026-10/<writer_id>.jsonl  # append-only usage events, merge-safe
```

**Status:** `1.1.0-draft`. The spec, JSON Schema and conformance fixtures are in place. The `aidus` CLI is planned ([cli/](cli/)).

## Why

- **Real numbers.** Usage is written by tools (agent hooks, agent logs, provider APIs), never by a language model guessing its own token count.
- **Merge-safe.** Each writer appends to its own shard, and `merge=union` keeps concurrent commits conflict-free.
- **Priced once.** Token buckets are disjoint. Input excludes cache, and output includes reasoning, so no token is counted twice.
- **Honest cost.** Every cost is labelled `authoritative`, `calculated`, `estimated` or `unknown`.
- **Safe to commit.** No prompts, code, conversations or credentials. Validators reject credential-shaped strings.

## Run the conformance suite

```bash
python -m venv .venv
.venv/Scripts/python -m pip install -r requirements-dev.txt   # Windows
# .venv/bin/python -m pip install -r requirements-dev.txt      # macOS/Linux
.venv/Scripts/python -m pytest
```

Fixtures are generated by `fixtures/*/generate.py`. CI regenerates them and fails if the output differs from the committed files.

## Claiming conformance

A tool may call itself *AIDUS 1.1 conformant* if it produces the expected outcome for every fixture (spec §11).
